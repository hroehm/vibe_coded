Programming Organization

Mastering the planning process for software development. Learn how to think like a computer and communicate effectively with your programming team.

The Planning Process

  • 1. Problem Identification: Identify the Inputs, Processes, Storage needs, and Outputs.
  • 2. Visualize Solution: Draw out how the problem will be solved using a Flowchart.
  • 3. Turn Visuals to Words: Write out the logic using Pseudocode.
  • 4. Document Work: Add comments to explain sections to other developers.
Why follow this process?
Jumping straight into writing code often leads to logic errors. By identifying inputs/outputs first, you define the problem's boundaries. Flowcharting visually catches infinite loops. Pseudocode helps refine the algorithm before worrying about specific language syntax.
Problem: Movie Rating App
Input: User's age (e.g., they type '14').
Process: Compare input age to rating requirements (Is 14 < 13? No. Is 14 < 17? Yes).
Storage: Store the age '14' as a variable.
Output: Appropriate MPA rating (Output "PG or PG-13").

Logic Concepts

Controls how a program behaves.

  • Branching (If-Then-Else): Changes in program sequence based on a logical test.
  • Looping: Repeats a block of code until a condition is met.
    • For Loop: Runs a specific number of times (uses a counter).
    • While Loop: Runs as long as a condition remains true.
Understanding the difference:
Use Branching when the computer needs to make a decision (e.g., "Is the password correct?").

Use a For Loop when you know exactly how many times an action should happen (e.g., "Print 5 tickets").

Use a While Loop when you don't know how many times an action needs to happen, but you know when it should stop (e.g., "Keep asking for a password until it's right").
Branching: If age < 13, show G rating. Else, check next condition.

For Loop: To display a countdown: For count = 5 down to 1, print count.

While Loop: While the user inputs letters instead of numbers for their age, display an error and ask again.

Flowcharts & Pseudocode

Flowchart Symbols:

  • Oval Start/End: Begins or terminates the flow.
  • Para Input/Output: Receiving data or displaying results.
  • Rect Process: Calculations or variable assignments.
  • Decision (Diamond): Logical test resulting in branching paths (Yes/No).

Pseudocode:

"Almost code" - human-readable algorithm description using keywords like IF, THEN, ELSE, WHILE.

// Movie Rating Snippet
IF age < 13 THEN
  DISPLAY "G"
ELSE IF age < 17 THEN
  DISPLAY "PG or PG-13"
END IF
Why use both?
Flowcharts are excellent for visualizing the "big picture" and tracking the paths a program can take, especially complex nested decisions. However, they can take up a lot of space. Pseudocode is much closer to actual programming. By translating a flowchart into pseudocode, you bridge the gap between a visual map and typing syntax into an IDE.
Flowchart to Pseudocode Example (Calculator):
Flowchart Shape: Parallelogram [Input Num1, Num2]
Translates to Pseudocode: ASK user for num1, num2

Flowchart Shape: Rectangle [Sum = Num1 + Num2]
Translates to Pseudocode: SET sum to num1 + num2

Flowchart Shape: Parallelogram [Output Sum]
Translates to Pseudocode: DISPLAY sum

Object-Oriented Methods (OOP)

Structures code by abstracting everyday concepts into common object templates.

  • Class: The template for similar objects (e.g., Human).
  • Properties: Attributes of the object (e.g., Height, Age).
  • Methods: Actions the object can perform (e.g., Walk(), Talk()).
The power of Objects:
Instead of writing hundreds of variables for a game with 10 enemies, you create one `Enemy` Class. Every time you spawn a new enemy, you instantiate a new Object based on that class. They all share the same Properties (Health, Speed) and Methods (Attack(), Move()), keeping code highly organized and reusable.
Class: Car
Properties (What it is/has): Color, Make, Model, CurrentSpeed, FuelLevel.
Methods (What it does): Accelerate(), Brake(), Refuel(), TurnOnLights().

Object Instance: MyCar (Red, Toyota, Corolla, 45mph, 50%)

Documentation & Comments

Crucial for explaining the program to other developers and yourself in the future. The computer ignores comments.

  • # - Used in Python, Ruby, Shell.
  • // - Used in Java, C++, JavaScript.
  • /* */ - Block comments for multiple lines.
Why Comment?
Code tells the computer *how* to do something. Comments tell humans *why* you did it that way. In professional environments, multiple people work on the same codebase. If you leave a project and return 6 months later, comments will save you hours of trying to decipher your own logic.
Python Example:
# Check if the user is old enough to drive
if age >= 16:

Java/C++/JS Example:
// Calculate total cost including 8% tax
let total = subtotal * 1.08;
